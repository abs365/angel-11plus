# Existing Platform Capability Reuse Assessment

**Programme:** Angel Assessment Transformation Execution Programme — Release 1
**Prepared:** 2026-08-11
**Method:** direct repository reconnaissance (file paths, function names, real behaviour — not assumed). Every claim below traces to a real file.

**Governing finding, stated once here rather than per-row:** the codebase contains **four parallel, historically-layered evidence systems** — legacy localStorage (`lib/progress.ts`, subject-level), the older ALI adaptive-mock engine (`lib/ali/*`, dotted skill codes), CSSE Learning Engine V1 (`EvidenceTier` ET-0..4), and CSSE Educational Intelligence Engine (`EducationalState`, 8-state). `lib/learningEngine/types.ts` documents (3) and (4) as *deliberately* separate models, not an oversight. Any personalisation work must build on the CSSE Educational Intelligence Engine (the most evidence-rigorous of the four) and explicitly not create a fifth parallel system.

## Classification Table

|---|---|---|---|
| Compute a competency's evidence-backed state | **REUSE** | `computeEducationalState()` (`lib/ali/educationalState.ts`), 8-state model, already gates on `validateCompetencyMastery()` not raw mastery_state | None for state computation itself |
| Recommend a priority competency from evidence | **REUSE** | `orchestrateRecommendations()` (`lib/ali/recommendationOrchestration.ts`) — real tiered system (wellbeing veto → direct evidence → shared-mechanism → exam-proximity) | Tier 2 (shared-mechanism/cross-competency) is documented as not-yet-generated (needs a Knowledge Graph, WP-20) |

| Let a family choose a focus area | **MISSING** | The mechanical lever exists (`weakSkills: Set<CompetencyCode>` param on `selectQuestions()`/`selectLearningUnit()`) but **no caller anywhere injects anything other than evidence-derived weak competencies into it.** No "pinned"/"forced" concept exists in `orchestrateRecommendations()`'s signature either. | This is the single largest EXTEND point the whole personalisation direction depends on — see Family Choice Model §2 |

| A second, independent "recommendation-vs-choice" architecture | **Not needed — do not build** | The existing 4-tier orchestration + explainability + wellbeing-veto stack is sufficient scaffolding; the only missing piece is a choice-injection parameter, not a parallel system | See Family Choice Model §2 for the specific extension point |

## Summary Verdict

**Three REUSE-heavy pillars already exist and are structurally sound: evidence computation, recommendation ranking, and explainability.** **One MISSING piece is small and precise, not architecturally large:** a way for a chosen competency (or set) to enter the same `weakSkills` parameter the evidence engine already uses — this is a parameter-injection extension, not a new subsystem. **One MISSING piece is genuinely larger:** a real, server-side Mock Attempt Ledger (today localStorage-only). **One area is blocked by frozen architecture, not by engineering:** WC-02 cannot be built until Assessment Brain V1 itself gains a Question Type for it — that is a Founder/architecture decision, out of this increment's scope to resolve.
