# Release 1 — Existing Content Authenticity Review Plan

**Programme:** Angel Assessment Transformation Execution Programme — Release 1
**Prepared:** 2026-08-10
**Status:** Plan only. The 29-item review this plan describes has explicitly **not** been performed — per the Founder's Stop Condition, this document explains how that review will later happen, it does not do it.

---

## 1. Purpose

Describe how the 29 questions currently live in `ali_question_bank` (18 original + 11 from migration 016, both currently Provisional Content per `RELEASE_1_ASSESSMENT_ELIGIBILITY_MODEL.md`) will later be evaluated against `RELEASE_1_CSSE_AUTHENTIC_QUESTION_SPECIFICATION.md`, once that review is separately authorised.

## 2. Why Existing Content Is Not Exempt

Per the Founder's Educational Authenticity Clarification: *"Do not preserve existing content merely because engineering work has already been completed around it... Judge it educationally."* Every one of the 29 items will be evaluated by the same standard as future original authoring — none is grandfathered in by virtue of already being live.

## 3. What the Review Will Check, Per Item

1. **Question Type mapping validity** — does the item's current tag hold up against the fuller characteristics now documented in the Specification (where that Question Type has been analysed to full depth), not just the original migration's own disclosed reasoning?
2. **Forced-fit status** — re-confirm the 6 items already self-disclosed as forced/approximate (`RELEASE_1_GAP_ANALYSIS.md` §4), and check whether any of the 23 "clean" items (12 original + 11 new) reveal a fit problem only visible once compared against the Specification's fuller field set.
3. **Traceability chain completeness** — can this item currently be walked back to a named CSSE Asset ID and question reference per the Specification §6 chain, or does it only trace to "this work package's own reasoned judgement" (the honest status the original migration comments already disclose)?
4. **Difficulty-label status** — cross-check against Increment 1's findings: the 3 already-identified rubric-mismatches (`mth-004`, `qa-010`, `mth-009`) remain open and unresolved by this plan; every other item's difficulty label remains Category D (provisional judgement) until this review.
5. **Educational soundness independent of CSSE-matching** — per the Founder's instruction not to remove content merely because it differs from a past-paper question: an item may be pedagogically sound (accurate, well-explained, UK-English-correct) even where its CSSE-authenticity evidence is thin. The review records both dimensions separately, not as one collapsed verdict.

## 4. Proposed Sequencing (not authorised to begin)

Mirrors Gate 1's own authoring priority, applied to review instead of authoring, so the same evidence work isn't duplicated twice:

1. **Batch 1 — the 6 self-disclosed weak items** (`mth-004`, `mth-003`, `mth-005`, `mth-007b`, `mth-006`, `wrt-003`): highest-priority review since Gate 2 requires an explicit remediate/retire/flag decision per item, and these already carry known, named weaknesses.
2. **Batch 2 — the 11 migration-016 items**: reviewed as their own batch given their distinct provenance (Live Question Bank Reconciliation Report), even though their evidentiary standard is otherwise identical to the original 18's clean items.
3. **Batch 3 — the remaining 12 clean original items**: lowest priority, since they already meet the Gap Analysis's Practice Eligible-equivalent bar and are not flagged with any known issue.

This sequencing is a proposal for a future increment's approval, not a schedule this plan commits to.

## 5. Who Performs the Review

Per the Eligibility Model's "no self-certification" rule (§3 of that document) and the Validation Strategy's Educational Validation requirement: the reviewer must be a qualified subject-matter reviewer who did not author the item's original Question Type tag — for all 29 current items, that is any qualified reviewer, since none has been reviewed by anyone but the original registering work package.

## 6. Output of a Future Review (format only, not content)

For each item, a future review would record: current status transition (per the Eligibility Model), pass/fail against each of the 5 checks in Section 3, and — where failed — whether the recommended action is remediate, retag, retire, or flag-and-retain. This plan does not pre-judge any individual item's outcome.

## 7. Explicit Non-Scope

This plan does not: review any item, change any item's status, change any item's tag or content, or estimate how long a real review would take. It exists solely so that when this review is authorised, it proceeds against a pre-agreed method rather than being improvised per-item.
