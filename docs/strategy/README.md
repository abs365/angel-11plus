# Angel Strategic Foundation & Product Philosophy

This folder contains Angel 11+'s permanent strategic documentation — the record of what the platform has become, the philosophy that governs how it should feel, and the principles every future feature, screen, and decision must be tested against. These are not phase reports to be superseded by the next build; they are the reference set the project answers to going forward.

## Recommended Reading Order

1. **`ANGEL_FOUNDATION_COMPLETE.md`** — Start here. What Angel is today: the build timeline, the architecture, ALI's real capabilities and limitations, and an honest launch-readiness verdict. Everything else in this folder assumes this context.
2. **`ANGEL_PRODUCT_EXCELLENCE_REVIEW.md`** — An independent, no-assumptions review of the product as it actually exists — navigation, journeys, age-banded student perspectives, parent trust, and a founder-level view of what could stop growth.
3. **`ANGEL_EXPERIENCE_MANIFESTO.md`** — The permanent philosophy. Defines how children and parents should feel at every stage, the invisible-intelligence doctrine, and the product principles every future decision is measured against. If a future feature contradicts this document, the manifesto wins.
4. **`ANGEL_PRODUCT_PHILOSOPHY_UPDATE.md`** — A permanent refinement to the Manifesto: which vocabulary should stay hidden (ALI's mechanism) versus which should always stay visible (Mock Exam, Assessment, Practice, Exam Readiness — the educational language families already trust).
5. **`ANGEL_CONNECTED_LEARNING_JOURNEY.md`** — How every individual experience — lessons, practice, missions, mocks, results, parent reports — should connect into one continuous story instead of separate modules.
6. **`ANGEL_MOMENTUM_FRAMEWORK.md`** — The permanent rule set ensuring every completion point in the product leads naturally to the next one. Builds directly on the Connected Learning Journey's findings.
7. **`ANGEL_VISION_2030.md`** — Read last. Where Angel could plausibly go over the next five years if it keeps the principles established in the documents above — not a feature roadmap, a description of an evolution grounded in what already exists.

## How to Use This Folder

Every document here carries a standard header (Title, Version, Status, Project, Phase, Owner, Last Updated, Purpose) so its status and scope are clear at a glance. When proposing a future feature or redesign, check it against `ANGEL_EXPERIENCE_MANIFESTO.md` and `ANGEL_MOMENTUM_FRAMEWORK.md` first — those two are the permanent, standing tests. The other five documents provide the evidence, reasoning, and context behind why those tests exist.
